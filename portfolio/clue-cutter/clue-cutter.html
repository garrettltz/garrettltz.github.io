AI-Assisted Multiplayer Game Development

Clue Cutter

A multiplayer browser party game where players create clues, remove some of them, and try to guess the hidden answer. Designed for 2–6 players using phones, desktop computers, and a shared TV display.

Project Overview

From party game concept to playable multiplayer website

My goal with Clue Cutter was to create a multiplayer browser game where players write clues, lose some of those clues, and then try to identify the hidden answer using the information that remains.

I designed the game around rotating player roles, five clues per round, a die that determines how many clues are erased, limited guesses, and scoring across multiple rounds.

Players can join a room without creating an account and use their phones or computers to participate, while a shared TV view presents the game to the entire group.

Process

How I built Clue Cutter

1. Defined the Game Rules

Planned rotating roles, five clues per round, a die that determines how many clues are erased, limited guesses, and scoring across multiple rounds.

2. Built the Game With AI Assistance

Used ChatGPT and Codex to turn my requirements into a playable website. I directed the design, reviewed the results, and requested changes through repeated testing.

3. Added Multiplayer Access

8. Published the Game

Deployed Clue Cutter as a playable website with a shared TV view and continued improving the game through testing and feedback.

Core Mechanic

Cutting the Clues

Each round begins with five clues for a hidden answer. Before the guessing phase, a die determines how many of those clues are erased.

The mechanic creates uncertainty because the guesser does not know which clues will survive. Players have to create clues that are individually useful while also hoping the most important information remains available.

Player Interaction

Typed and Handwritten Clues

I wanted phones to feel like game controllers rather than simply smaller versions of the desktop interface. Players can enter clues normally or draw them using a mouse or finger.

The game also grew to include custom prompts, selectable avatars, room chat, audience reactions, and voting for funny wrong guesses. These features were added to make players who were not currently guessing feel involved in the round.

Guessing

Working With Limited Information

After the clues are cut, the remaining information is shown to the guesser. The player has a limited number of attempts to identify the hidden answer.

This became the central tension of the game: enough information needs to survive for the answer to be possible, but removing clues makes each round less predictable.

Special Mechanic

Spotlight Wager

I added the Spotlight Wager to create higher-stakes moments during the game. The guesser receives a single attempt with increased points on the line.

Spotlight rounds use their own presentation and audio cues so the moment feels different from a standard turn.

Results

Scoring and Audience Reactions

At the end of each round, the shared display presents the outcome, updated scores, and audience reactions.

Reactions and voting were designed to keep the rest of the group involved instead of making the game only about the player whose turn is currently active.

Multiplayer Design

Joining, reconnecting, and playing across devices

I designed Clue Cutter so players could join a game without creating an account. A room code allows the group to connect to the same session from their own devices.

The game supports both phones and desktop computers, while the shared TV presentation provides a central screen for the group.

Reconnect support was also included so a temporary disconnection would not automatically remove a player from an active game.

Visual Direction

Building the puppet-theater identity

I chose a purple puppet-theater style to give Clue Cutter its own recognizable identity. The interface uses curtains, stage elements, audience silhouettes, music, and sound effects to make the shared display feel like a performance.

Pip, a bunny puppet mascot, became part of that identity and is used throughout the game to add personality and provide reactions during different moments.

Mascot & Animation

Bringing Pip to life

I used AI-generated artwork to develop multiple Pip assets, including reading, writing, and detective activities.

I then directed how those assets should behave in the interface, including blinking, arm movements, and reactions connected to round outcomes.

Pip also became an important part of the interface testing process. I repeatedly adjusted placement and sizing so the mascot remained visible without covering important game information.

Testing & Iteration

Using problems on screen to guide revisions

A large part of the development process involved repeatedly testing the game and reviewing screenshots of the interface.

Testing revealed issues including cluttered layouts, unclear controls, animation clipping, inconsistent mascot sizing, wasted screen space, and differences between phone and desktop layouts.

Instead of treating the first working version as finished, I used those problems to direct additional revisions to the layout, instructions, animations, and overall presentation.

Development

AI-Assisted Workflow

I used ChatGPT and Codex as development tools to help turn my game requirements into a playable website.

My role was to define the game concept, plan features and mechanics, direct the visual design, review implementations, playtest the game, identify problems, and decide what needed to change.

AI tools assisted with implementation and artwork. I continued directing the project through repeated testing and revisions rather than treating the initial generated result as the finished game.

My Role

Concept, direction, testing, and iteration

My responsibilities included the game concept, rules and mechanics, feature planning, visual direction, player experience, playtesting, and iterative review.

I also made decisions about how the phone and TV experiences should differ, how players should interact during each phase, how Pip should be incorporated into the presentation, and which issues needed to be prioritized during revisions.

What I Learned

From an idea to a playable multiplayer game

Clue Cutter gave me experience thinking through multiplayer game flow, shared game state, reconnect behavior, responsive interfaces, touch input, visual feedback, and player interaction across different devices.

It also gave me practical experience using AI as part of an iterative development process. Clear requirements mattered, but testing the result and identifying what did not work was just as important.

Next Steps

Playtesting and continued refinement

My next step is to test Clue Cutter with larger groups and use that feedback to continue refining pacing, clarity, interface behavior, and the overall multiplayer experience.
